  <how-to-verify>
    Open http://localhost:3000 in Chrome. Open DevTools (Network tab, filter by "stt-token").

    **Test 1 — Token security (STT-03):**
    1. Click Ask Parz to open voice mode
    2. In DevTools Network tab, look for a POST request to /api/stt-token
    3. Click it → Preview/Response tab
    4. Confirm: response body is `{ "token": "..." }` — NOT the raw API key string
    5. Confirm: the request body is empty (no API key sent from browser)

    **Test 2 — Basic STT in Chrome (STT-01, STT-02):**
    1. With voice mode open, say "Hello Parz" clearly
    2. Confirm: partial transcript text appears in the VoicePanel caption while speaking
    3. Confirm: after 1-2 seconds of silence, the committed transcript triggers the Parz AI response
    4. Confirm: Parz speaks a reply

    **Test 3 — Barge-in threshold:**
    1. Trigger a voice query and wait for Parz to speak a response
    2. Stay silent while Parz speaks
    3. Confirm: Parz does NOT interrupt itself mid-response (old behavior with 0.15 threshold)
    4. Try talking loudly while Parz speaks — confirm barge-in still works when you genuinely interrupt

    **Test 4 — Cross-browser (STT-02):**
    Open http://localhost:3000 in Firefox or Safari.
    1. Click Ask Parz → voice mode opens
    2. Say something
    3. Confirm: transcript appears (ElevenLabs Scribe works via WebSocket in all browsers)
    4. If transcript does NOT appear: note whether /api/stt-token request was made in DevTools

    **Test 5 — Fallback (optional, STT-02):**
    To verify fallback: temporarily rename .env.local ELEVENLABS_API_KEY to break it, restart dev, try voice in Chrome.
    - Expected: /api/stt-token returns 503 → fallback to Web Speech API → voice still works in Chrome

    If any test fails, describe: which test, what you saw, any console errors.
