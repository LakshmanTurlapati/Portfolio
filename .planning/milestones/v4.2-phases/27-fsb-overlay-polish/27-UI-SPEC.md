# Phase 27 — UI Design Contract: FSB Overlay Polish

> Visual and interaction contract for FSB-04 (dynamic action captions) and FSB-05 (mobile-tuned overlay treatment). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of decisions:** All visual / behavioral choices are pre-locked in `27-CONTEXT.md` (per-tool caption strings, 1500ms success / 3000ms error timings, 768px mobile breakpoint, hide grid on mobile, larger touch-target badge). This document formalizes those decisions into tokens and acceptance specs.
>
> **Post-v4.2 overlay correction (2026-04-28):** This spec covers only the global Parz action-caption overlay (`FsbControlOverlay`). The project/right preview overlay is owned by `IframeViewer`'s `PreviewControlOverlay` (`fsb-preview-control-overlay`) and must not be mapped back to the removed right-side ProjectDetail panel.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Caption inline gap (between activity dot and caption text) |
| sm | 8px | Badge vertical padding (existing) |
| md | 12px | Mobile badge horizontal padding (existing 600px CSS rule) |
| md+ | 16px | Desktop badge horizontal padding (existing); badge offset from viewport edge: `max(16px, env(safe-area-inset-*))` |
| lg | 24px | Grid corner inset (existing); grid background-size unit |
| xl | 32px | (not used directly in this phase) |
| 2xl | 48px | Reserved for caption fade-in transform offset (none — caption fades in place) |

**Exceptions:**

- `corners inset: 16px` on `<= 600px` (existing CSS rule, kept) — non-multiple-of-4-friendly because `mask-image` math depends on it; do not change.
- Badge target hit area on mobile must measure **≥ 44px in the smaller dimension** (Apple HIG / WCAG 2.5.5) — achieved through padding + font-size + caption width. Current mobile rule `padding: 8px 12px; font-size: 9px` produces ~28px tall badge; **Phase 27 must enlarge** to meet 44px.

## Color

The FSB overlay is intentionally monochrome (Phase 19 / Phase 23 baseline). No new color is introduced in Phase 27.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | inherits page background (`var(--color-bg)`: `#FFFFFF` light / `#000000` dark) | Page surface — the overlay is transparent and renders on top |
| Secondary (30%) | `rgba(var(--fsb-overlay-rgb), 0.07)` badge surface; `rgba(var(--fsb-overlay-rgb), 0.22)` corner border | Badge fill, grid lines, target reticle, corners |
| Accent (10%) | `rgb(var(--fsb-overlay-rgb))` (= `0,0,0` in light mode / `255,255,255` in dark mode) | Badge text, active caption text, corner tick highlights |
| Destructive | not applicable | The overlay does not surface destructive actions; tool-error is communicated via `voice-glow` red shadow + caption duration extension (3000ms) — **no color shift inside the overlay itself** |

**Accent reserved for:**

- Badge label text (`powered by FSB`)
- Caption text during `tool-executing` / `tool-success` / `tool-error` windows
- Corner tick highlights at `0.32` alpha

**Explicitly NOT colored:**

- Caption does NOT change color on `tool-error`. Error state is communicated solely by (a) the existing red `voice-glow-error` overlay (separate component), and (b) extended caption duration (3000ms vs 1500ms). This is per CONTEXT deferred-ideas: "Per-tool color hints in the badge — out of scope; monochrome remains."

## Caption State Machine (FSB-04)

This is the load-bearing visual contract for FSB-04. Planner / executor must implement this exact behavior.

### States

| State | Trigger | Visible badge content | Duration |
|-------|---------|-----------------------|----------|
| `idle` | overlay mounted, no tool active | `powered by FSB` | indefinite (until `active` prop flips) |
| `executing` | VoiceBus `tool-executing` event fires | tool-specific caption (table below) | until `tool-success` or `tool-error` arrives |
| `success` | VoiceBus `tool-success` event fires | last caption persists | 1500ms, then transitions to `idle` |
| `error` | VoiceBus `tool-error` event fires | last caption persists | 3000ms, then transitions to `idle` |

### Per-Tool Captions (locked in CONTEXT, restated here for planner reference)

| Tool name | Caption (source case) | Rendered case (uppercase via CSS) | Args needed |
|-----------|----------------------|-----------------------------------|-------------|
| `openProject` | `Opening {projectName}…` | `OPENING {PROJECTNAME}…` | `args.projectName` (display name; e.g., `FSB / Full Self Browsing`) |
| `scrollTo` | `Scrolling…` | `SCROLLING…` | none |
| `closeBrowser` | `Closing browser…` | `CLOSING BROWSER…` | none |
| `toggleTheme` | `Switching theme…` | `SWITCHING THEME…` | none |
| `openLink` | `Opening link…` | `OPENING LINK…` | none |
| `openCurrentProjectExternal` | `Opening externally…` | `OPENING EXTERNALLY…` | none |
| `navigate` | `Navigating to {page}…` | `NAVIGATING TO {PAGE}…` | `args.page` (route name: `portfolio` / `about` / `home`) |

**Fallback:** If `tool-executing` fires for an unknown tool name, render the desktop default `powered by FSB` rather than crash.

### Timer & Cleanup Rules

- Each `tool-success` or `tool-error` arms a single timer ref. Subsequent events cancel and re-arm.
- On unmount, all pending timers must be cleared (existing `useEffect` cleanup pattern from `voice-glow.tsx` lines 69-73 is the precedent).
- `active=false` (overlay deactivated by `site-control-provider`'s 900ms hide) does NOT need to clear the caption immediately — the overlay is unmounted (`if (!mounted || !active) return null`).
- Rapid-fire tool calls: latest `tool-executing` event wins (no caption queue). Per CONTEXT deferred-ideas: "Animated caption transitions between rapid-fire tool calls — current pattern: latest event wins."

### Caption Animation

- Fade-in: 200ms `ease-out`, opacity 0 → 1, no transform.
- Fade-out (state → idle): 200ms `ease-in`, opacity 1 → 0.
- The `powered by FSB` ↔ caption swap is a cross-fade through `idle` opacity 0 step OR a direct text swap on `tool-executing` — **executor's choice**, but `prefers-reduced-motion: reduce` must short-circuit to no-animation (instant text swap).
- No layout shift between `powered by FSB` and the longest caption (`Navigating to portfolio…` → ~25 chars uppercased) — badge `min-width` should accommodate the longest expected caption. Recommended `min-width: 220px` desktop, `min-width: 180px` mobile.

## Mobile Treatment (FSB-05)

| Aspect | Desktop (≥ 768px) | Mobile (< 768px) |
|--------|-------------------|------------------|
| `.fsb-control-grid` (full-bleed scan grid) | visible (existing animation 1.6s linear infinite) | **hidden** (gate via `useMediaQuery` returning `false` → render `null` for the grid div, OR via `hidden md:block` on the grid div) |
| `.fsb-control-corners` | visible (24px inset, 18px radius) | visible (16px inset, 14px radius — existing 600px rule still applies; **kept for visual continuity between 600-768px** unless planner consolidates) |
| `.fsb-control-target` reticle | 64px circle, full opacity | 44px circle at 0.7 opacity (existing 600px rule) |
| `.fsb-control-badge` | 10px font, 8px / 16px padding, badge ~28px tall | 11px font, 12px / 16px padding (NEW), letter-spacing `0.14em`, badge **must measure ≥ 44px tall × ≥ 88px wide for hit area** |
| Caption visibility | yes | yes (same content, slightly smaller text per typography table) |
| Pointer behavior | container `pointer-events: none` (existing `.fsb-control-overlay` has `pointer-events-none` Tailwind class). Badge inherits `pointer-events: none`. **Must not change in Phase 27.** | identical — overlay must not block taps on underlying content |

**Breakpoint reconciliation:**

The existing CSS uses `@media (max-width: 37.5rem)` (= 600px). Phase 26 / CONTEXT-27 specify `useMediaQuery('(max-width: 768px)')` for new mobile work. Planner must decide:

- **Recommended:** Migrate the existing 600px CSS `@media` rules to use the 768px JavaScript hook, so all FSB overlay mobile behavior is gated by a single source of truth. Update `.fsb-control-grid` visibility, badge sizing, and `corners` / `target` adjustments to be conditionally applied via React (data attribute or className) rather than CSS media query.
- **Acceptable alternative:** Keep the CSS `@media (max-width: 37.5rem)` as-is for `corners` / `target`, and gate only the grid + badge size changes in JS at 768px. This produces a tiny "in-between" zone (600-768px) where corners / target use desktop sizing but grid is hidden. Document this explicitly.

PLAN must pick one and document the chosen reconciliation.

**Pointer-safety acceptance test:** Tap-through must work in the bottom-left badge zone on a 375px viewport. The badge sits at `position: fixed; bottom: max(16px, env(safe-area-inset-bottom)); left: max(16px, env(safe-area-inset-left))`. Verify by clicking a portfolio card whose footer overlaps the badge area on mobile.

## Accessibility Acceptance

- [ ] `aria-hidden="true"` retained on the visual overlay div (existing).
- [ ] `<span role="status" aria-live="polite">` retained and updated dynamically with caption text (lowercased, terminating `.`) per the Copywriting Contract.
- [ ] Badge text contrast ≥ WCAG AA at 10px / 11px against the badge surface. The badge surface is `rgba(--fsb-overlay-rgb, 0.07)` over the page background; the text is `rgb(--fsb-overlay-rgb)` at full opacity. In light mode, black text on near-white surface; in dark mode, white text on near-black surface. **Both pass AAA.**
- [ ] `prefers-reduced-motion: reduce` honored: caption fade animation reduced to instant text swap; existing `.fsb-control-grid { animation: none !important; }` rule retained.
- [ ] Pointer-events behavior preserved: container `pointer-events: none`, no descendant overrides to `auto`.
- [ ] Mobile badge hit area ≥ 44×44 CSS px (Apple HIG / WCAG 2.5.5).

## Interaction State Matrix

| State | Caption text | Caption opacity | Badge animation | Voice glow (separate component) | SR status text |
|-------|--------------|-----------------|------------------|--------------------------------|----------------|
| overlay inactive (`active=false`) | n/a (overlay unmounted) | n/a | n/a | follows VoiceBus state | n/a |
| overlay active, idle | `powered by FSB` | 1 | none | none / listening / etc. | `Parz is controlling the site.` |
| `executing` | tool caption | fades 0 → 1 over 200ms ease-out | none | `voice-glow-executing` (steady) | `Parz is {caption lowercased}.` |
| `success` (1500ms hold) | last caption | 1 | none | `voice-glow-success` (1000ms one-shot) | `Parz is {caption}.` |
| `error` (3000ms hold) | last caption | 1 | none | `voice-glow-error` (red, persists) | `Parz is {caption}.` |
| post-success / post-error timer fires | `powered by FSB` | fades 1 → 0 → 1 over 200ms ease-in / 200ms ease-out | none | follows VoiceBus state | `Parz is controlling the site.` |
