<objective>
Eliminate concurrent / overlapping TTS in voice mode by introducing a central cancellation primitive (`cancelAllAudio`) and wiring it into every entry point that can produce audio. Add a turn-generation counter so old `handleUserTurn` invocations bail at await checkpoints when a newer turn has started. Closes the five overlap modes catalogued in `22-AUDIT.md` (O-1 through O-5).
</objective>

<tasks>

<task id="1" type="execute">
<read_first>
- src/lib/voice-controller.ts
</read_first>
<action>
Add four new refs at the top of `useVoiceController`: `speakResolverRef`, `speakAbortRef`, `speechUtteranceRef`, `turnGenerationRef`. Implement `cancelAllAudio()` as a `useCallback` that aborts the in-flight `/api/tts` fetch, stops the current `BufferSource`, drops the tracked `SpeechSynthesisUtterance` and calls `synth.cancel()`, unblocks any pending speak Promise via the resolver ref, stops the RMS loop, and clears `speakingRef`. It must NOT mutate `VoiceBus.state` — the caller decides the new state.
</action>
<acceptance_criteria>
- Four new refs exist with correct types: `MutableRefObject<(() => void) | null>`, `MutableRefObject<AbortController | null>`, `MutableRefObject<SpeechSynthesisUtterance | null>`, `MutableRefObject<number>`.
- `cancelAllAudio` is a `useCallback` with empty deps (`[]`).
- The helper is wrapped in try/catch around external API calls (`abort`, `stop`, `synth.cancel`, the resolver invocation) so a failure on one cleanup path doesn't skip the others.
</acceptance_criteria>
</task>

<task id="2" type="execute">
<read_first>
- src/lib/voice-controller.ts (`streamTTS`)
</read_first>
<action>
Refactor `streamTTS` to use the new primitives. At entry, call `cancelAllAudio()` to preempt any prior speak. Track the new Promise's resolver in `speakResolverRef` and the new `AbortController` in `speakAbortRef`. Pass `signal: ac.signal` to the `fetch`. Check `ac.signal.aborted` at every `await` boundary in the `.then` chain (after the fetch, after `arrayBuffer()`, after `decodeAudioData`) and bail silently. In the `.catch`, check for `AbortError` / `ac.signal.aborted` and bail before falling back to SpeechSynthesis. Identity-check the source in `onended` (`if (audioSourceRef.current === source)`) before mutating state. Apply the same identity-check pattern to the SpeechSynthesis fallback via `speechUtteranceRef`. Call `synth.cancel()` before `synth.speak(u)` in the fallback.
</action>
<acceptance_criteria>
- `streamTTS` first line inside the Promise constructor calls `cancelAllAudio()`.
- `speakResolverRef.current = resolve` is set immediately after.
- An `AbortController` is created and stored in `speakAbortRef.current`.
- `fetch('/api/tts', { ..., signal: ac.signal })` is the new fetch shape.
- Three `if (ac.signal.aborted) return;` guards in the `.then` chain.
- `if (ac.signal.aborted || (err instanceof Error && err.name === 'AbortError')) return;` guard at the top of `.catch`.
- `onended` wraps state mutation in `if (audioSourceRef.current === source) { ... }`, but always calls `resolve()` after.
- The synth fallback path tracks `speechUtteranceRef.current = u`, calls `synth.cancel()` first, and identity-checks `u` in `onend` / `onerror` (shared `finishSynth` helper acceptable).
- `streamTTS` `useCallback` deps are `[cancelAllAudio]`.
</acceptance_criteria>
</task>

- No new tests in this plan. Deferred. Manual smoke checks listed in `22-VERIFICATION.md`.
- The original audit's "Bonus: 300-500ms debounce on bargeIn" item is NOT in this plan. The state-guard at the top of the `level` listener (`if (state === 'speaking' && ...)`) already prevents same-window re-entry; explicit debounce is a P3-level polish.
</deviations>
