  <what-built>
    The circular reveal transition (View Transitions API + WAAPI clip-path on ::view-transition-new(root))
    was restored by removing all hero-nav-btn CSS rules and classes that caused duplicate
    view-transition-name values and aborted transitions silently.

    What the animation does:
    - Clicking a nav button calls navigateWithReveal(path, clickX, clickY)
    - document.startViewTransition() captures old page snapshot
    - router.push() loads new page content
    - transition.ready fires: WAAPI animates ::view-transition-new(root) with clipPath
      from circle(0px at clickX clickY) to circle(maxRadius at clickX clickY)
    - Old page is visible outside the expanding circle throughout the 500ms animation
    - Animation uses cubic-bezier(0.455, 0.03, 0.515, 0.955) easing (power2.inOut feel)
  </what-built>
  <how-to-verify>
    Run the dev server: npm run dev

    Test these navigation paths in order:

    1. HOME → PORTFOLIO
       - Click the Portfolio button (large rounded rectangle in navbar)
       - Expected: circular reveal expands from the center of that button outward
       - Expected: home page (particles, snow, etc.) visible outside the expanding circle
       - Expected: portfolio page slides in behind the expanding circle
       - Expected: animation completes in ~500ms

    2. PORTFOLIO → HOME (back button)
       - On portfolio page, click the back button (top-left arrow button)
       - Expected: circular reveal expands from the back button position
       - Expected: portfolio page visible outside the expanding circle
       - Expected: animation completes in ~500ms

    3. HOME → ABOUT
       - Click "About Me" in the desktop navbar or bottom nav on mobile
       - Expected: circular reveal from About Me link position
       - Expected: smooth 500ms animation

    4. HOME → CHAT
       - Click "Ask Parz" or chat icon
       - Expected: circular reveal from that button position

    5. BROWSER BACK BUTTON
       - Navigate to /portfolio, then click browser back
       - Expected: circular reveal from screen center (fallback origin for popstate)

    Failure signs to watch for:
    - Instant page switch with no animation: transition.ready .catch() fired — hero-nav-btn still present
    - Animation plays but old page disappears immediately: CSS animation on old(root) not suppressed
    - Page nav locks up (stuck): isTransitioningRef guard not resetting — .catch() handlers missing

    Open browser DevTools Console. No errors should appear related to view transitions.
    If you see "DOMException: The document's pending view transition was skipped" in console,
    the transition aborted — report the nav path that triggered it.
  </how-to-verify>
