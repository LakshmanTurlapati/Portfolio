## Overview

v4.1 made Parz feel recognizably like Lakshman: a public-safe persona with current-work, flagship-project, and personality grounding; portfolio content aligned to that identity; project openings rerouted through one approved inbuilt-browser path; expanded global site-control tooling; an FSB-inspired control overlay; deterministic verification; a complete voice-pipeline audit with three waves of fixes (hardcoded-tour rip-out, audio serialization, dynamic LLM-driven greet, mobile + iOS safe-area pass).

The milestone shipped in two halves: phases 16-20 were the planned scope (persona, browser path, site control, FSB overlay, regression coverage). Phases 21-24 were audit-driven follow-on filed retroactively after the planned scope landed and the user reported breakage in voice and mobile that the verification suite hadn't covered.

## Milestone Summary

**Decimal Phases:** None (all phases are sequential integers).

**Key Decisions:**
- Public-safe persona is sourced from a typed `public-profile.ts` module, not from inline strings in the system prompt — keeps prompt and visible content in sync via Phase 20 source-parity tests.
- Project openings resolve through a local alias map + approved-target table, never model-generated URLs (SAFE-06).
- FSB control overlay lifecycle lives in `SiteControlProvider` so text and voice control actions share one visible feedback path.
- Verification is local Vitest contracts + a focused Playwright E2E running on port 3100; no live Grok / ElevenLabs / Amplify dependency in tests.
- Voice tours are LLM-driven via existing tools (Phase 21) — no hardcoded `TOUR_STEPS` array.
- Voice audio serialization uses a centralised `cancelAllAudio()` + AbortController + turn-generation counter (Phase 22).
- Voice output is 100% LLM-generated (Phase 23) — only `isStopIntent` remains hardcoded for instant-abort UX.
- iOS safe-area requires `viewport-fit=cover` on the Next.js viewport export — without it, every `env(safe-area-inset-*)` formula resolves to 0 (Phase 24).

**Issues Resolved:**
- 17-finding voice audit (`21-AUDIT.md`) — Wave 1 P0 closed (F-01, F-02, F-03, F-04).
- Five overlapping-voice modes (`22-AUDIT.md`, O-1..O-5).
- Hardcoded greet / empty-response / server-error speech (Phase 23 H-1, H-2, H-3).
- Phase-22 barge-in regression that silenced all TTS on the live deploy (Phase 23 R-1 hotfix).
- AudioContext autoplay policy keeping ctx suspended after first speak (Phase 24).
- Mobile navbar slot overflow (Phase 24).
- iOS notch / dynamic island / home indicator overlapping fixed mobile elements (Phase 24).

**Issues Deferred:**
- Wave 2 P1 audit findings still open in `21-AUDIT.md`: F-05 (openTextChat 400ms race), F-06 (STT session-started timeout), F-07 (SpeechSynthesis timeout), F-08 (registerToolCallbacks deregister), F-09 (tool callback try/catch).
- API-03: Live Amplify / custom-domain smoke test of `/api/chat`, `/api/stt-token`, `/api/tts` (script ready at `scripts/verify-amplify-apis.mjs`, blocked on a reachable production URL).
- Particle-background mobile performance.
- Chat input iOS keyboard handling.
- Project-detail full-screen mobile UX.
- FSB-04 (overlay action captions), FSB-05 (mobile-specific overlay treatment).
- CHAT-UI-01 (chat popup/page visual redesign).

**Technical Debt Incurred:**
- Voice path retains one hardcoded trigger (`isStopIntent`) for instant-abort safety — accepted; everything else is LLM-driven.
- Diagnostic console.warn logging was added to API routes during Phase 24 diagnosis and removed in the same phase. Brief inflight blip in commit history.
