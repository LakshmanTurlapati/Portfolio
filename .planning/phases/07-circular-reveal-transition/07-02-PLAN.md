<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
    The circular reveal page transition has been rewritten to use the View Transitions API. When you click any navigation element, the browser:
    1. Captures a pixel snapshot of the current page (::view-transition-old(root))
    2. Navigates to the new page
    3. Clips the new page inside an expanding circle originating from where you clicked, while the old page remains visible around the circle
    4. The old page stays visible until the circle fully covers the viewport

    This matches Flutter's ClipPath + Stack behavior: you see your origin page content around the expanding new page — not a solid color overlay.
  </what-built>
  <how-to-verify>
    Open http://localhost:3000 in Chrome 111+ (or Edge 111+, Firefox 133+, Safari 18+).

    **Test 1 — Basic reveal from Portfolio button (TRAN-01):**
    1. On the home page, click the "Portfolio" button in the navbar
    2. EXPECTED: A circle expands from where the Portfolio button is. Inside the circle you see the portfolio page content. Outside the circle you still see the home page background/content. The animation takes about 500ms.
    3. PASS if: The home page is visible around the expanding circle
    4. FAIL if: A solid color (black or white) replaces the home page before the new page appears

    **Test 2 — Old page visible throughout animation (TRAN-02):**
    1. While on the portfolio page, click the back arrow or any nav link
    2. EXPECTED: The old page content is visible around the expanding circle for the full duration of the animation (not briefly flashed, not faded)
    3. PASS if: Old page content is clearly visible outside the circle at all times during animation
    4. FAIL if: Old page flickers, fades, or is replaced by a solid color at any point

    **Test 3 — Origin point accuracy (TRAN-01):**
    1. Click the "About Me" link in the navbar
    2. EXPECTED: The circle expands from approximately the center of the "About Me" text/link
    3. PASS if: Circle origin is at or very near the clicked element

    **Test 4 — Rapid click guard (D-13):**
    1. Click any nav link, then immediately click again rapidly
    2. EXPECTED: Only one transition runs; the second click is ignored
    3. PASS if: No double-animation or janky transition occurs

    **Test 5 — Browser back button (D-07):**
    1. Navigate to the portfolio page using a nav click
    2. Press the browser back button
    3. EXPECTED: A circular reveal plays from approximately screen center (not from the nav element position)
    4. PASS if: The transition animates instead of an instant page swap

    **Note on browser support:** If testing in an older browser without View Transitions support, the GSAP solid-color overlay will run instead — this is expected (D-05 fallback). The visual inspection for TRAN-01/02 requires a supported browser.
  </how-to-verify>
  <resume-signal>Type "approved" if all 5 tests pass. If any test fails, describe which test failed and what you observed (e.g., "Test 1 failed — still seeing solid black overlay before new page appears").</resume-signal>
