# Phase 26 -- UI Design Contract: Mobile UX Pass

> Visual and interaction contract for MOB-01 (mobile particles), MOB-02 (iOS chat keyboard), MOB-03 (project-detail mobile layout). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Source of truth: this spec carries CONTEXT.md's locked decisions into prescriptive tokens, states, and acceptance specs. The Flutter parity mandate from CLAUDE.md governs all visual choices -- this phase tunes existing components for mobile, no new visual language.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (manual) |
| Preset | not applicable |
| Component library | none -- raw React + Tailwind v4 + CSS variables |
| Icon library | react-icons (FA6 set) |
| Font | Lato (`--font-lato`), Instrument Serif (`--font-instrument-serif`), JetBrains Mono / Space Mono (inline stack) |

**Why no shadcn:** Project mandate (CLAUDE.md) is pixel-perfect Flutter parity. Existing tokens live in `src/app/globals.css` as `--color-*` CSS variables and Tailwind v4 `@theme` block. Adding shadcn would create a parallel, conflicting token system. This phase consumes the existing token system unchanged.

**Existing breakpoint convention (must reuse):**
- Tailwind `sm` = 600px (`37.5rem`) -- Flutter parity, declared in `globals.css` `@theme` block
- Tailwind `md` = 768px (default)
- Tailwind `lg` = 1024px (default)

**Mobile detection contract for this phase (MOB-01 specific):**
- Use `window.matchMedia('(max-width: 768px)')` -- LOCKED by CONTEXT.md
- Reuse `src/hooks/use-media-query.ts` (already provides matchMedia + listener cleanup)
- Do NOT use `innerWidth` polling, do NOT use `useEffect` with `resize` listener directly
- Tablet (>768px and <1024px): receives desktop particle count (90)

**Padding ladder for `project-detail.tsx` (MOB-03, LOCKED):**

```
mobile (<768px):  px-4
md   (>=768px):   md:px-8
lg   (>=1024px):  lg:px-14   (preserves current desktop behaviour exactly)
```

Apply to: `<header>`, body container `<div>`, `<footer>`, and `mx-*` on the cover image (cover image becomes `-mx-4 md:mx-8 lg:mx-14`).

**Cover-image full-bleed contract (MOB-03, LOCKED):**
- Mobile (<768px): cover image escapes container with `-mx-4` (negative margin matching `px-4`); border-radius is removed mobile-only OR reduced to `rounded-none` for true full-bleed feel
- md and up: cover image returns to `mx-8` then `lg:mx-14` -- matches parent padding
- Aspect ratio `aspect-video` preserved at all breakpoints

**Stats grid contract (MOB-03, LOCKED):**
- Mobile (<768px): `grid-cols-2` (2 columns), gap-4
- md and up: existing `grid-template-columns: repeat(auto-fit, minmax(140px, 1fr))` preserved
- Switch via Tailwind responsive class on the wrapper -- replace inline `gridTemplateColumns` style with `className="grid grid-cols-2 md:grid-cols-[repeat(auto-fit,minmax(140px,1fr))] gap-4"`

**iOS safe-area inset contract (MOB-02, LOCKED):**
- Apply `env(safe-area-inset-bottom)` ONLY to the chat-input wrapper (the `<div style={{ padding: '8px 16px 16px' }}>` at line 498-503)
- Pattern: `paddingBottom: 'max(16px, env(safe-area-inset-bottom))'`
- Do NOT apply left/right insets in this phase (landscape notch deferred per CONTEXT.md)
- Do NOT apply `safe-area-inset-top` -- not in scope

Exceptions: 36px chat-input send-button (existing, preserved -- not a touch-target issue because input wrapper is large enough).

## Interaction & Motion Contract

This is the load-bearing section for Phase 26. Each interaction is prescribed for the executor.

### MOB-01: Mobile particles

| Property | Value |
|----------|-------|
| Detection | `useMediaQuery('(max-width: 768px)')` from `src/hooks/use-media-query.ts` |
| Mobile particle count | 45 (LOCKED) |
| Desktop / tablet particle count | 90 (existing, preserved) |
| Density `value_area` | unchanged (900) |
| Breathing rAF loop | runs at native 60Hz on mobile -- NO fps cap, NO throttle (LOCKED) |
| Reinitialization on breakpoint cross | YES -- particle count change requires `destroypJS()` + re-call `particlesJS()`. Use the existing teardown sequence at lines 73-80 |
| Theme cross within same breakpoint | Existing behavior preserved -- already triggers reinit via `isDark` dep |
| Connect-line distance | unchanged (150) |
| Move speed | unchanged (1.2) |

**Acceptance:**
- iPhone SE (375px): 45 particles render, no visible jank during VoiceBus breathing
- iPhone 14 Pro (393px): same as above
- iPad portrait (768px): exactly at boundary -- spec calls for desktop count (90) at >=768px, so iPad portrait (768px) gets 90; iPhone Pro Max (430px) gets 45
- Desktop resize from 1200px -> 700px: particle count switches to 45, no console errors, no orphaned canvas
- VoiceBus `level > 0.01`: breathing loop still modulates opacity / line distance smoothly with reduced count

### MOB-02: iOS chat keyboard

| Property | Value |
|----------|-------|
| `inputMode` | `text` (LOCKED) |
| `enterKeyHint` | `send` (Claude's discretion -- aligns with the existing send-on-Enter behavior) |
| `autoComplete` | `off` (Claude's discretion -- chat input is conversational, not a form field) |
| `autoCorrect` / `spellCheck` | left at browser default (preserve current iOS behavior) |
| Focus scroll behavior | LOCKED -- `onFocus` -> `setTimeout(() => inputRef.current?.scrollIntoView({block:'center', behavior:'smooth'}), {DELAY})` |
| Focus-scroll delay | 300ms (Claude's discretion within CONTEXT.md's "small setTimeout"). Rationale: iOS keyboard slide-up animation is ~250ms; 300ms gives the keyboard time to take its final viewport bite before we measure. |
| `scrollIntoView` options | `{ block: 'center', behavior: 'smooth' }` (LOCKED) |
| VisualViewport API | NOT used in this iteration (LOCKED -- deferred) |
| Safe-area inset | bottom only -- `paddingBottom: 'max(16px, env(safe-area-inset-bottom))'` on the input wrapper (LOCKED) |
| Safe-area inset left/right | NOT applied (LOCKED -- landscape notch deferred) |
| Disabled state during loading | preserved -- `disabled={isLoading}` |

**Acceptance:**
- iPhone SE Safari: tap chat input -> keyboard slides up -> input scrolls smoothly into vertical center of remaining viewport within ~600ms total
- iPhone 14 Pro Safari (notched): tap chat input -> keyboard slides up -> input is fully visible above keyboard, NOT obscured; bottom padding respects home-indicator safe area
- Android Chrome: same focus-scroll pattern works (matchMedia + scrollIntoView are universal); no regression
- Desktop / non-touch: focus still calls scrollIntoView, but on a non-scrollable popup it's a no-op -- no visual regression
- Reduced motion: `behavior: 'smooth'` respects `prefers-reduced-motion` automatically (browser-level honoring)
