# Phase 29 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Boundary

This is a behavior-boundary phase, not a visual redesign. The Legacy V2 chat popup and full `/chat` page must remain visually unchanged from the v4.2 DART-refined baseline. Site-control behavior moves out of text chat and remains voice-only.

| Surface | Contract |
|---------|----------|
| `src/components/chat-popup.tsx` | Preserve existing glass popup, header, subtitle, message bubbles, suggestion chips, loading state, error state, input, close behavior, focus behavior, and morph animation. Remove invisible site-control request/dispatch wiring only. |
| `src/app/chat/page.tsx` | Preserve existing full-screen chat layout, back button, empty state, message bubbles, suggestion chips, loading state, error state, and input. Remove invisible site-control request/dispatch wiring only. |
| `src/app/api/chat/route.ts` | Text chat remains conversational. Voice requests remain tool-capable via `isVoice: true`. |

Interaction rule: text chat must never navigate, open project previews, scroll the shell, scroll project previews, close/open browser surfaces, toggle theme, open arbitrary links through tools, run tours, switch modes through tools, or trigger the FSB site-control overlay. Those actions belong to voice mode.

Copy rule: when a user asks text chat for site control, Parz answers briefly in text: "I can talk through that here, but use voice mode for navigation and site-control actions." The assistant may still explain where to go or what to look for conversationally.

No new visible banner, persistent warning, modal, tooltip, badge, or CTA should be added for this boundary. The guidance appears only as an assistant response when the user asks for an advanced control action.

## Visual No-Change Guardrails

Primary visual anchor remains the active chat transcript/input area, with header/status secondary.

| Area | Requirement |
|------|-------------|
| Layout | Keep popup desktop size at max 400px wide and 600px tall, mobile inset at 8px, and full `/chat` as `h-dvh` with the existing safe-area padding. |
| Header | Keep "Parz", the existing status dot, and "Legacy V2 Chat interface (Features may be limited)". Do not add persistent voice-mode instructions. |
| Messages | Keep user/assistant bubble alignment, max widths, rounded corners, blur, borders, and linkified assistant text. |
| Suggestions | Keep the current randomized one-small/one-big suggestion chip pattern and hide-after-use behavior. |
| Loading | Keep the rotating loading messages, shimmer text, and three-dot wave. |
| Errors | Keep randomized Parz-persona error messages and red error treatment; do not expose raw technical errors. |
| Voice handoff | Opening text chat from voice remains a UI handoff only. It must not make the text chat transport or client tool-capable. |

## Interaction Contract

| Interaction | Required Behavior |
|-------------|-------------------|
| Ordinary text chat | User sends a message; Parz answers normally about persona, portfolio, projects, and broad topics. No tool parts should be requested or executed. |
| Text site-control request | Parz returns a concise conversational redirect to voice mode. No page navigation, project viewer, scroll, theme toggle, browser close/open, external open, or overlay appears. |
| Text transport | Use the default chat transport with no `enableSiteControl` body and no `isVoice` flag. |
| Text client tool parts | Text clients must not import `useSiteControl`, parse assistant tool parts, keep handled-tool refs, or dispatch tool calls. If a malformed assistant response includes tool parts, the text UI ignores them. |
| Voice mode | Voice continues sending `isVoice: true`; `/api/chat` exposes `siteControlTools`; `voice-controller` and `voice-session-provider` continue dispatching tools through the existing voice path. |
| Links in chat answers | Normal URL linkification remains allowed. Clicking a normal anchor is not a site-control tool action. |
| Keyboard | Enter sends when input is non-empty and not loading. Escape closes the popup. Full `/chat` back button keeps existing reveal navigation. |
| Accessibility | Preserve dialog role, `aria-modal`, `aria-labelledby`, message log live region, loading status, alert role, visible focus outlines, `aria-label` values, and reduced-motion behavior. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline dot gaps |
| sm | 8px | Compact element spacing, mobile popup inset |
| md | 16px | Default element spacing, message rhythm |
| lg | 24px | Desktop popup viewport margin unit |
| xl | 32px | Page-level horizontal safety spacing |
| 2xl | 48px | Desktop popup viewport margin total |
| 3xl | 64px | Major full-page chat side padding |

Exceptions: preserve existing Legacy V2 pixel values already present in chat surfaces, including 5px, 6px, 7px, 9px, 11px, 12px, 13px, 15px, 18px, 20px, 22px, 25px, 30px, 44px, 52px, 400px, and 600px. These are visual-baseline exceptions only; do not introduce new off-scale spacing in this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg)` = `#FFFFFF` light / `#000000` dark | Page background and primary text/surface inversion system |
| Secondary (30%) | `rgba(255,255,255,0.6)` dark popup / `rgba(0,0,0,0.6)` light popup | Legacy popup glass surface, assistant/user bubble surfaces, chips |
| Accent (10%) | `#00E676` | Popup healthy status dot and its glow only |
| Destructive | `#ef4444` | Error status dot, error border, and error bubble only |

Accent reserved for: popup healthy status dot, popup healthy status glow. Do not use accent for new buttons, links, banners, or site-control guidance.

Existing `/chat` assistant links may keep Tailwind blue link colors. This phase must not expand the palette.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Send message |
| Empty state heading | Start a conversation |
| Empty state body | None rendered in this phase; keep the existing quiet empty state and suggestion chips. |
| Text site-control guidance | I can talk through that here, but use voice mode for navigation and site-control actions. |
| Error state | Use existing randomized Parz-persona errors, e.g. "Ah, my brain glitched for a sec. Try again?" Never show raw `error.message`. |
| Destructive confirmation | None: this phase has no destructive actions. |

Tone: direct, warm, brief, and conversational. Do not imply that text chat performed a control action. Do not apologize at length or add a persistent tutorial.
